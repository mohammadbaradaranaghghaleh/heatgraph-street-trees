# HeatGraph

Code, data pipeline and interactive explorer for the paper

> **Physics-informed graph surrogates for exposure-weighted street-tree allocation: generalisation to unseen cities and independent verification with SOLWEIG**
> <!-- TODO(authors): author list, journal, year, DOI -->

HeatGraph chooses where to plant a limited number of street trees so that the heat dose
pedestrians actually receive goes down as much as possible, while keeping that cooling fairly
spread across districts. It combines:

- a calibrated 2.5D radiation and UTCI engine;
- a heterogeneous graph neural network (GNN) surrogate with physics-informed crown-shadow edges;
- split-conformal uncertainty;
- gravity-model pedestrian flows;
- NSGA-III multi-objective optimisation.

Every reported layout is re-simulated with the engine. The Pareto designs for Rotterdam Centrum
are also checked independently with SOLWEIG-GPU.

Headline results (all regenerated by `reproduce.py`):

| Result | Value |
|---|---|
| Engine vs SOLWEIG-GPU Tmrt, 4 held-out patch-days | MAE 1.30–1.62 K |
| GNN error on tree-induced ΔUTCI, unseen city (Rotterdam) | 0.063 °C |
| GNN error on tree-induced ΔUTCI, unseen city with imputed heights (Freiburg) | 0.075 °C |
| Optimised vs random layouts, engine-verified heat-dose reduction | 1.8–6.0× more |
| Practitioner rule (sunniest, busiest streets), share of greedy's reduction | 46–85 % |
| Same rule without pedestrian flow, share of greedy's reduction | 29–71 % |
| NSGA-III without greedy seeding, share of greedy's reduction | 60–91 % |
| Between-district inequality (Theil) at 90 % of greedy cooling | up to 8.2 % lower |
| SOLWEIG-GPU per-segment correlation of ΔUTCI with the GNN / engine | 0.91–0.94 / 0.95–0.97 |
| Total cooling underestimated by engine / GNN, relative to SOLWEIG-GPU | 10–20 % / 11–21 % |

## Quick start: reproduce every figure and table

Allow about 5 minutes for setup and under 1 minute to run, on CPU. This needs Python 3.11 and the
data archive.

```bash
git clone https://github.com/mohammadbaradaranaghghaleh/heatgraph-street-trees.git heatgraph && cd heatgraph
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu    # or .../whl/cu130 for a GPU
pip install -r requirements.txt
# download heatgraph-data-<date>.zip from <DATA_DOI> and extract it here (it creates data/...)
python scripts/make_release_archive.py --verify    # SHA-256 check of all 215 released files
python reproduce.py                                 # regenerate + compare all 7 figures and 7 tables
```

`reproduce.py` is non-destructive. It changes nothing in `figures/`, `tables/`, `manuscript/` or
`data/`. It performs these steps:

1. Regenerates F1–F7 and T1–T6 from the released results into `reproduction/<timestamp>/`.
2. Checks that every table (CSV, Markdown, LaTeX) is **byte-identical** to `tables/`.
3. Checks that every figure matches `figures/*.png` pixel by pixel, with a tolerance of 2 % of pixels.
4. Rebuilds the manuscript's numeric facts in a scratch folder and compares them with `manuscript/facts.json`.
5. Runs `manuscript/check_numbers.py`, which audits every number in the text against those facts.

It exits with code 0 only if everything matches and writes `reproduction_report.json`.
Add `--tests` to also run the unit-test suite (85 tests, about 1 minute; 3 are skipped unless the raw
downloads are present).

The exact environment used for the paper is in `requirements-lock.txt`, a full `pip freeze`
including `torch==2.14.1+cu130`.

## Interactive dashboard

The dashboard runs from a plain clone: no data archive, GPU or PyTorch needed.

```bash
pip install -r dashboard/requirements.txt     # streamlit, altair, matplotlib, numpy, pandas
streamlit run app.py                          # opens http://localhost:8501
```

It reads only `dashboard_data/` (17.8 MB, versioned) and `tables/*.csv`. `dashboard_data/` is a
compact extract of the released results, built by `scripts/build_dashboard_data.py`: tree-induced
UTCI changes are stored at 0.001 °C resolution instead of the full float arrays. For Streamlit
Community Cloud, deploy `dashboard/streamlit_app.py`. It runs `app.py` unchanged, and its folder holds
the light `dashboard/requirements.txt`, so the cloud build skips the full pipeline dependencies.

The dashboard is read-only and shows the same results as the paper. Choose a test patch (three Rotterdam
patches or Freiburg), a planting budget, an hour, and two methods to compare. The tabs are:

- **Placements**: side-by-side maps of new trees and per-segment ΔUTCI for NSGA-III (GNN), NSGA-III
  (linear), greedy, the two practitioner rules (sun × flow, sun only) and random layouts, with dose
  reduction, Theil index and tree count.
- **Benchmark**: dose reduction against budget for each method, including the practitioner rules and
  NSGA-III without greedy seeding, with the random spread, each rule's share of greedy's reduction and the
  hypervolume of the unseeded front.
- **Pareto front & equity**: the cooling–equity front coloured by Theil index. Pick a layout (maximum
  cooling, most equal at ≥ 90 % of greedy cooling, or any by id) to see its map and its change against greedy.
  Below, the per-district dose reductions of greedy and the equity-selected layout.
- **SOLWEIG check**: Rotterdam Centrum only. SOLWEIG-GPU, engine and GNN cooling maps for the
  verified Pareto designs, with mean cooling on a common mask and the engine's local over-prediction.
- **Robustness**: the sensitivity analysis (Table 7, plus this patch per setting), coverage of the
  conformal margin, and NSGA-III results over five random seeds.
- **Data & models**: all seven tables of the paper.

A headless test of the dashboard is in `tests/test_dashboard.py`.

## Full pipeline (from public downloads)

`python reproduce.py --full` runs every step below in order and then performs the verification.
Run it in a **fresh clone**: it refuses to run while released results are present, unless
`--i-understand-this-overwrites-results` is given. Each step can also be run on its own.

| # | Step | Script | Writes | Used in |
|---|---|---|---|---|
| 1 | Download buildings, network, places, canopy and weather for 18 patches | `scripts/01_ingest.py --execute` | `data/raw/<patch>/` | T1 |
| 2 | Ingestion QA table | `scripts/ingest_summary.py` | `data/raw/ingest_summary.csv` | T1 |
| 3 | Freeze raw data (SHA-256 per file; later steps verify it) | `scripts/freeze_dataset.py` | `data/raw/FROZEN.json` | all |
| 4 | Calibrate engine on one patch-day; evaluate 4 held-out patch-days against SOLWEIG-GPU | `scripts/02_solweig_benchmark.py --calibrate … --evaluate …` | `data/validation/` | T2, F1 |
| 5 | Counterfactual plantings labelled by the GPU engine (81 × 36 h per patch) | `scripts/04_generate_dataset.py` | `data/processed/<patch>/` | training |
| 6 | Train GNN surrogates (geometric / crown-shadow edge features; GATv2 ablation; leave-patch-out validation) | `scripts/05_train_surrogate.py` | `data/models/` | T3, F2, F3 |
| 7 | Linear physics surrogate | `scripts/06_baselines.py` | `data/models/metrics_linear_physics.json` | T3, F2 |
| 8 | Error by planting density | `scripts/07_density_analysis.py` | `data/models/density_analysis.json` | F4 |
| 9 | Optimisation benchmark: NSGA-III (GNN, linear), greedy, random; conformal intervals | `scripts/08_benchmark.py` | `data/stage5/` | T4, T5, F5, F6 |
| 10 | SOLWEIG-GPU verification of 5 Pareto designs (Rotterdam Centrum) | `scripts/09_solweig_verify.py` | `data/stage5/rot_centrum/` | T6, F6, F7 |
| 11 | Physics-feature correlation (reported in the text) | `scripts/11_feature_correlation.py` | `data/models/physics_feature_corr.json` | text |
| 12 | Practitioner heuristics, NSGA-III without greedy seeding, SOLWEIG comparison on a common mask | `scripts/12_revision_experiments.py` | `data/stage5/<patch>/revision_r2r3.json`, `data/stage5/revision_r4_verification.json` | T4, T6, F5 |
| 13 | Conformal coverage, per-district equity, sensitivity analysis, NSGA-III seed stability | `scripts/13_revision_round2.py` | `data/stage5/revision_round2_*.json` | T7, text |
| 14 | Figures and tables | `scripts/10_figures_tables.py` | `figures/`, `tables/` | all |

`scripts/03_patch_search.py` documents how three patches were re-centred to match their intended
typology. Its result is already recorded in `configs/patches.toml`, so it is not part of the default run.

Requirements and caveats for a full re-run:

- **GPU.** Steps 5–10 were run on an NVIDIA RTX 5070 with CUDA 13.0 (`torch==2.14.1+cu130`). Use the
  `cu130` wheel: RTX 50-series cards need CUDA 12.8 or newer. If you replace a CPU build of torch,
  uninstall it first, because pip treats `2.14.1+cpu` and `2.14.1+cu130` as the same version.
- **SOLWEIG-GPU** (steps 4 and 10) runs in its own conda environment because it needs GDAL:
  ```bash
  conda env create -f environment-solweig.yml
  conda run -n solweig-ref python -m pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cu130
  conda run -n solweig-ref python -m pip install solweig-gpu==2.0.1
  ```
  HeatGraph calls it as a separate program through `conda run -n solweig-ref`.
- **Downloads.** Step 1 fetches about 230 MB from public services. Upstream datasets (3DBAG,
  Overture releases, the canopy-height tiles, the weather archive) can change. `--full` keeps the paper's
  `data/raw/FROZEN.json`, and step 5 stops if any downloaded file differs from it. To continue with the
  newer data on purpose, delete `data/raw/FROZEN.json` and run `--full` again, which re-freezes the data.
- **Determinism.** GPU training is not bit-reproducible, so a full re-run gives numbers close to the
  paper's, not identical ones. The released archive is what the paper reports, and the default
  `reproduce.py` mode reproduces it exactly.
- **Within-patch-validation rows of T3** (`metrics_edgemlp.json`, `metrics_gatv2.json`) were produced by an
  earlier revision of the training script. `reproduce.py --full` approximates them with
  `--val-mode planting --dropout 0 --weight-decay 1e-5 --epochs 60`.

Maintainers build both archives with `python scripts/make_release_archive.py [--with-rasters]`; the
output goes to `dist/` together with `SHA256SUMS.txt`. Raw downloads are not redistributed. Step 1
re-fetches them, and `FROZEN.json` verifies them.

- 3DBAG building heights (Netherlands);
- Overture Maps buildings, transportation and places;
- the global 1 m canopy-height map (Meta / WRI);
- the ERA5-based Open-Meteo historical weather archive.

## Methodological limitations

These are stated in the paper and apply to anything derived from this code:

- **Population proxy.** District population, which weights the equity objective, is approximated by building floor area from 3DBAG heights. No census data are used, and all vulnerability weights are one.
- **Trip generation.** The gravity model generates the same number of trips at every network node and uses Overture places as destinations. Other assumptions, such as residential origins, could change the selected layouts.
- **SOLWEIG verification on one patch.** The independent SOLWEIG-GPU check of optimised layouts covers one patch (Rotterdam Centrum, one heat day). The engine itself is validated on four held-out patch-days.
